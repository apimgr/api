# API Reference

The REST API uses the version configured by `server.api_version` in `server.yml`; the default is `v1`. The base path is `/api/{api_version}/`. Utility routes are public. Server management routes use the credential rules documented in [Security](security.md).

## Request and response format

Use the method shown in the route table. Path and query values are supplied in the URL; POST operations accept JSON or form data as supported by the endpoint. Successful JSON responses use the `{"ok": true, "data": ...}` envelope (HTTP 200 unless the route table specifies another success status). Errors use the canonical `{"ok": false, "error": "CODE", "message": "...", "details": {...}}` envelope; `details` is omitted when there is no structured context, and the HTTP status carries the status code. Health endpoints use their documented flat health response. Routes ending in `.txt` return `text/plain`. Image routes return raw image bytes with a format-specific image content type; generated QR codes, avatars, barcodes, and identicons return PNG.

## Shared server endpoints

- `GET /api/autodiscover` is the unversioned CLI discovery endpoint. It returns the running project/API version and checksum-verified operator-provisioned CLI artifacts; exposed Tor/I2P addresses appear only when the service is active and its `expose` setting is enabled. See [Integrations](integrations.md) for public discovery behavior.
- `GET /api/{api_version}/cli/binaries/{api-cli-os-arch}` serves an operator-provisioned CLI release binary after verifying its published checksum. Downloads are public by default; `cli.binary_download.require_auth` requires a valid Bearer token.
- `GET /server/i2p/status` is a loopback-only status endpoint for the server CLI and does not expose key material.

- `GET /server/healthz` and `GET /api/{api_version}/server/healthz` report server health. `/healthz` is an optional HTML health alias controlled by `server.healthz.root.enabled`; `/api/healthz` is the unversioned API alias.
- Health statistics expose aggregate request totals and rolling 24-hour counts; totals are persisted in `server.db`, while health and metrics probes are excluded from those request counters.
- `GET /server/about`, `/server/privacy`, `/server/dpo`, `/server/contact`, `/server/help`, `/server/terms`, `/server/security`, and `/server/security/policy` serve the public server pages.
- `GET /api/{api_version}/server/about` returns the About page as JSON (`title`, Markdown or configured `content`, and `format`); content is never rendered HTML.
- `GET /api/{api_version}/server/privacy` returns the public privacy information as JSON, including cookie categories, collection, use, security, sharing, retention, rights, third parties, DPO contact, and resolved page URLs.
- `GET /api/{api_version}/server/auth/check` is a machine-only Bearer-token check: `200` returns the credential `kind` (`operator` or `owner`), and `401` reports an invalid or missing token without echoing it.
- `GET /server/tracking.js` serves the configured same-origin analytics loader only after analytics consent; it returns `404` when disabled, unconsented, or requested over Tor/I2P.
- `GET /api/{api_version}/server/help` and `/api/{api_version}/server/help/mcp` return JSON help documents; `/server/help/mcp` is the corresponding HTML page.
- `GET`/`POST /api/{api_version}/server/contact` expose the public contact form contract and two-step submit/review flow. A valid `security_id` selects the coordinated-disclosure fields; the response includes a fresh CAPTCHA descriptor and form token.
- The contact review response contains only `review.type`, `review.email`, and `review.subject`, plus the review token and delay. On confirmation, clients repeat the original submitted fields unchanged; the server resolves an HTTPS researcher-key URL only after validating the review token.
- `GET /api/{api_version}/server/dpo` returns the configured DPO name and public contact email, plus the request-resolved absolute privacy URL. The email falls back from `server.contact.dpo.email` to `server.contact.general.email`; it never exposes the admin address.
- `GET /api/{api_version}/server/terms`, `GET /api/{api_version}/server/security`, and `GET /api/{api_version}/server/security/policy` return JSON mirrors of the public terms and security information.
- `GET /server/preferences` and `POST /server/preferences` read and update guest preferences in browser cookies; `GET`/`POST /server/preferences/sync` and `GET /server/preferences/sync/import` transfer preferences between browsers without storing them server-side.
- `GET`/`POST /api/{api_version}/server/preferences` read and partially update guest preferences; `GET /api/{api_version}/server/preferences/sync` exports them and `GET /api/{api_version}/server/preferences/sync/import` imports them.
- `GET /api/healthz` is the direct unversioned health alias.
- `GET /api/swagger` serves the generated OpenAPI JSON; the versioned server route is `/api/{api_version}/server/swagger`.
- `GET` and `POST /api/graphql` and `/api/{api_version}/server/graphql` serve read-only GraphQL queries; `/server/docs/graphql` is the browser interface.
- `/server/docs/swagger` is the browser interface for OpenAPI.
- `POST /api/{api_version}/server/reports/{name}` accepts sanitized browser Reporting API reports. Supported report names include CSP, NEL, deprecation, intervention, crash, and `default`.
- Metrics routes are mounted only when `server.metrics.enabled` is true. `/server/metrics[/{service}]`, `/api/{api_version}/server/metrics[/{service}]`, and `/api/metrics[/{service}]` are aliases; `/metrics[/{service}]` is also mounted when `server.metrics.root.enabled` is true. Services are `prometheus`, `grafana`, and `loki`; each requires its configured Bearer token unless unauthenticated access is explicitly enabled.
- Prometheus includes `api_owner_tokens_active{kind="primary"|"linked"}` gauges for active, non-revoked, unexpired owner tokens. The Grafana dashboard covers scheduler, system, and owner-token metric categories alongside HTTP, database, and cache metrics.

### Owner and linked token management

Owners are anonymous, credential-only identities. There are no user accounts or passwords. The primary owner token grants access to that owner's resources and manages linked tokens; linked tokens grant the same resource access but cannot manage credentials. API routes accept Bearer credentials only and ignore browser cookies. Token-management operations require the primary owner token, except issuing a new primary token, which requires no credential and returns `409` if a valid token is already supplied.

| Method | API route | Credential | Behavior |
|--------|-----------|------------|----------|
| `POST` | `/api/{api_version}/server/preferences/tokens/primary` | None | Issues a new owner and primary token (`201`). |
| `GET` | `/api/{api_version}/server/preferences/tokens` | Primary owner Bearer token | Lists the primary and linked tokens in masked form. |
| `POST` | `/api/{api_version}/server/preferences/tokens/primary/reveal` | Primary owner Bearer token | Reveals the primary token in the response body. |
| `POST` | `/api/{api_version}/server/preferences/tokens/primary/rotate` | Primary owner Bearer token | Replaces the primary token in place; linked tokens and resources remain valid. |
| `DELETE` | `/api/{api_version}/server/preferences/tokens/primary` | Primary owner Bearer token | Deletes the owner, all its tokens, and all its resources. |
| `POST` | `/api/{api_version}/server/preferences/tokens` | Primary owner Bearer token | Creates a linked token. Supply a name (1–64 characters), scope (`read` or `read-write`, default `read-write`), and either `expires` (`never`, `7d`, `30d`, `90d`, `1y`) or `expires_on` (today or a future UTC date); both expiry fields cannot be supplied together (400). Duplicate names or the active-token limit return 409. The response returns its value as `linked_token` and includes its scope. |
| `POST` | `/api/{api_version}/server/preferences/tokens/{id}/reveal` | Primary owner Bearer token | Reveals one linked token in the `linked_token` response field. |
| `POST` | `/api/{api_version}/server/preferences/tokens/{id}/rotate` | Primary owner Bearer token | Rotates one linked token in place and returns its new value as `linked_token`; the primary and other linked tokens remain valid. |
| `PATCH` | `/api/{api_version}/server/preferences/tokens/{id}` | Primary owner Bearer token | Changes any supplied combination of `name`, `expires` (`never`, `7d`, `30d`, `90d`, `1y`), or `expires_on` (today or a future UTC date). Omitted fields keep their current values; `expires` and `expires_on` cannot both be supplied. Invalid values return 400, a duplicate name returns 409, and an unknown linked token returns 404. |
| `DELETE` | `/api/{api_version}/server/preferences/tokens/{id}` | Primary owner Bearer token | Revokes one linked token. |

The API returns raw primary token values as `owner_token` and raw linked token values as `linked_token`, only from issue, reveal, and rotate operations. Token objects in list responses contain masked values and a `scope` of `global`, `read`, or `read-write`. Read-scoped linked tokens can call only GET, HEAD, and OPTIONS MCP tools; a write requiring a higher scope returns 403 with `WWW-Authenticate: Bearer error="insufficient_scope"`. Token-management routes are never exposed as MCP tools. Browser token management is available at `/server/preferences/tokens`; its POST forms use the owner cookie and CSRF protection. See [Security](security.md) for credential handling and the page's restore behavior.

## Content negotiation

API routes default to JSON. `Accept: application/json` takes precedence over client detection; `Accept: text/plain`, non-interactive HTTP clients, and API paths ending in `.txt` select plain text. The text serializer emits a declared primary value by itself, formats structured results as `OK: {message}` followed by ordered `key: value` fields, and formats errors as `ERROR: {code}: {message}` while retaining the HTTP status. Scalar lists are printed one item per line; nested objects use dot-separated keys. Health has its own flat `key: value` layout. MCP is JSON-RPC and does not use this negotiation.

Frontend pages default to HTML, explicit `Accept: text/plain` and curl-style HTTP tools receive formatted terminal text, and text browsers receive server-rendered HTML without scripts. Forms continue to work without JavaScript. Image operations return their documented image media type when the response is an image.

## Interactive references

The GraphQL endpoint is query-only and accepts GET and POST requests. GET uses
`query`, optional JSON `variables`, and optional `operationName` query
parameters; POST accepts those fields as JSON. GET requests cannot run
mutations. A request without `query` returns a short plain-text usage message,
which makes the no-JavaScript GraphQL documentation link useful.

GraphQL follows its response format rather than the REST `ok` envelope.
Successful requests return `{"data": ...}`. Parse, validation, and execution
errors return HTTP 200 with `data` set to `null` or partial data and an `errors`
array whose entries include `extensions.code`. Requests rejected before
GraphQL execution, such as malformed JSON or malformed GET variables, use the
standard API error envelope and their corresponding HTTP status.

- OpenAPI UI: `/server/docs/swagger`
- OpenAPI JSON: `/api/swagger`
- GraphQL UI: `/server/docs/graphql`
- GraphQL endpoint: `/api/graphql` (GET and POST; queries only)

For CLI access, see [CLI Reference](cli.md). For credential and rate-limit behavior, see [Security](security.md).
